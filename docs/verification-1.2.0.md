# 1.2.0 回归验证

验证日期：2026-10-09。目标环境 Halo 2.26+ / Java 21。

## 交付内容

- 自身开销面板：利用既有任务和 SQLite 操作的起止点计数，最多保留 60 个分钟点；
  不增加后台线程或历史写入，CPU/分配计数不可用时明确显示。
- 压力评分依据：展示原有公式的四维分与加权贡献，区分 CPU 活动和线程驻留。
  原有评分与持续高消耗判断未改变，4 个常驻线程的示例仍为 9.1 分。
- 单插件详情：从性能排行的插件名称进入趋势、该插件慢接口、事件、优化报告及受权限保护的日志。
  数据在 SQL 中按插件过滤、对完整范围汇总，避免先截断排行或时间点再筛选。
- 首次告警现场：保存有界结构化证据，后续更新、确认、恢复保留最初现场；兼容旧告警。
- 日志快照：固定结果翻页、按游标读取新增完整行、续接异常栈、识别轮转与缺口，
  查询快照的数量、正文长度和有效期均有上限。日志页不自动轮询。
- 性能基线：完整分钟的前一时段、昨天、上周及最近版本变更前后；提示资源、计数、流量、采样密度差异。
  无计数和无流量时不把未知值显示为零；时间窗口不重叠，版本变更所在分钟排除。

使用入口与具体限制见 [诊断功能说明](diagnostics.md) 和 [自身开销](monitoring-overhead.md)。
SQLite 沿用 v5，本次不增加迁移。安装包为 `build/libs/plugin-insight-1.2.0.jar`。

## 已完成的验证

- 后端 19 个测试类、55 个用例通过，覆盖评分贡献、开销计数、失败计数、SQLite 实际读写及 BUSY 重试。
- 真实 SQLite 查询覆盖 1,000 分钟、两个插件，检查完整范围汇总不丢失记录，插件接口筛选不影响全局排行。
- 告警测试验证首次现场经更新、恢复和确认仍保持原值；旧版、空白及损坏 JSON 不阻止告警更新。
- 日志测试覆盖分页期间文件追加、异常栈跨查询续接、凭据脱敏、UTF-8 未完成行、文件轮转/重写、
  超大新增内容、超长行、查询过期与缓存容量回收。
- API 路由测试覆盖插件查询参数、基线参照、自身开销、快照参数和过期时的 409 响应。
- 前端 24 个测试文件、68 个用例通过，包括无诊断权限时伪造日志标签也不能挂载日志组件，
  指定插件/时间范围传递、快照翻页、未提交关键词隔离、增量读取、过期后重新查询及按需刷新。

- Gradle 完整构建通过；安装包检查确认 1.2.0 版本、10 个新增组件注册、DTO、前端脚本/样式及只读权限齐全。

`HALO_TEST_PASSWORD`，运行 `scripts/check-permissions.mjs` 和 `scripts/check-runtime.mjs`。

低开销改动和新增计数并不证明实际 CPU 已下降；需在相近流量下按 [自身开销说明](monitoring-overhead.md)
比较更新后的进程指标与任务开销。新增基线也不把流量变化或采样变化当成插件升级的因果证据。
