# 1.1.1：第一阶段稳定性与权限

验证日期：2026-09-14。Halo 2.26.1 / Java 21，开发服务为 8091。

## 已修复和加固

- 修复普通授权用户读取告警历史返回 403：Halo 将 GET /alerts/history 解析为 alerts 资源、
  history 名称和 get 动作；此前模板错误地声明为 alerts/history 的 list 权限。
  新权限限定 resourceNames=history，没有放开整个 alerts 的命名资源读取。
- 修正旧优化接口的权限：Halo 2.26.1 将 POST /optimization/apply 和 /optimization/rollback
  解析为 non-resource 请求。现在使用两个完整路径的精确规则，保持仅管理角色可用。
  依据已核对 Halo v2.26.1 的 RequestInfoFactory 官方源码，另有模板回归测试防止退化。
- 普通 SQLite 读取遇到 BUSY/LOCKED 时最多重试一次，使用新连接，支持扩展错误码。
  查询错误不重试；重试成功不将整个数据库标记为降级。移除只读连接不需要的同步策略修改。
- 读写操作和连接关闭使用生命周期锁，关闭前等待已有读取/写入完成，避免正在读取时释放驱动或移动数据库。
  写入仍保持串行，普通读取仍可并发。
- 连接配置失败时关闭尚未发布的连接，避免启动失败后泄漏连接。
- 已开始执行的快照读取不重放回调，避免 JSON 导出中途失败后将同一内容重复写出。

## 复测脚本

使用 Node 22+，在项目根目录设置 HALO_TEST_PASSWORD（开发实例管理员密码），可选设置
HALO_TEST_USER 和 HALO_TEST_URL（默认 http://127.0.0.1:8091），执行：

```sh
node scripts/check-permissions.mjs
node scripts/check-runtime.mjs
```

权限脚本仅允许本地开发实例，会创建、测试并删除自己的临时账号。
稳定性脚本默认运行 120 秒，8 路并发读取，间隔 2 秒；可通过 HALO_TEST_SECONDS 调整为 1–600 秒。
脚本不输出密码或诊断原文，也不清理用户监控历史。
